# 分批實作順序

這是同一次「全版美術」工作的交付順序。後續批次仍在範圍內，不以優先級為理由永久省略。正式實作從 game/index.html 開始，樣板資料獨立。

| 批次 | 內容 | 完成證據 |
|---|---|---|
| M0 基準與資料映射 | 執行語法檢查、隔離存檔、記錄原畫面；確認面板可達性、繪圖共用、換裝／連線入口 | 基準、物件映射、可重現啟動與測試方式 |
| M1 共用 UI 與核心布局 | tokens、順線元件、左右戰鬥／管理、裝備比較、素質摘要、焦點與提示 | 三個桌機視窗；長名稱／大數字；不遮掉戰鬥必要資訊 |
| M2 即時裝備與掉落 | 所有換裝入口接到能力同步、背包 item.id、掉落通知與整理、存檔與連線同步 | ACCEPTANCE 的 live-gear／資料一致性案例，原遊戲持續自動戰鬥錄影或狀態記錄 |
| M3 全系統介面 | 封面、主選單、養成其餘頁、任務、收藏、戰地、商店、挑戰、設定、連線、彈窗 | COVERAGE 所有 UI 列有截圖或空殼／舊入口判定證據 |
| M4 全世界與戰鬥美術 | 玩家／轉職／外觀、13 敵方母型及變體、9 寵物、5 神獸、10 場景、動作、HUD、預警、掉落／門與特效 | 母型聯絡表、變體抽樣、各畫質同場景、判定與視覺對照 |
| M5 事件演出與整體驗收 | 轉蛋、升級、結算、少動態、全流程／存檔／連線／效能回歸、打包 | 可玩版本、前後對照、測試結果、已知限制、最終提交 |

每批採可檢視的小提交，更新 STATUS、COVERAGE 的實作欄與 evidence。遇到差異先查原碼／資料，不為追求與樣板假數值一致而更動正式公式。正式頁面不能留下樣板開關、DEMO 或假功能按鈕。

回復方式：保留原基準檔及各批提交；不改寫遠端歷史。若某項驗收未通過，修復相關批次並記錄阻礙；不得將未測試項目寫成已通過。
