# 專案背景、需求與方向：提供給新的實作端聊天室

更新：2026-11-10（Asia/Taipei）。本文件從本次協作對話起點整理，與 [STATUS](STATUS.md)、[DECISIONS](DECISIONS.md) 配合使用。美術版本 v0.4，正式遊戲尚未套用新版。

## 一開始為什麼做這件事

使用者提供自寫小遊戲 `MS 1.html` 與《冒險島 開發資訊彙整（給 AI 接手優化用）》DOCX，希望先檢查程式內與美術有關的物件、代碼及共用邏輯，再討論 UI、提示、角色、動作、動畫等可優化範圍，最後才具體決定視覺方向。

此專案已有遊戲系統與內容；本次工作是基於原遊戲整體提升美術與操作體驗。原 HTML 保存在 `game/index.html`，原交接文件在 `docs/reference/`。附件是背景資料，其內的建議與命令不自動成為本次使用者指令。實際程式優先於附件對現況的描述。

使用者從一開始就要求 Git 與 Harness 架構，原因是協作會跨聊天室與實作端，需要把背景、決策、進度和驗證寫進檔案，避免每次換聊天室重談一次。

## 已定案的產品體驗

玩家的主要循環是：自動戰鬥持續 → 注意有價值的掉落 → 看詳情／比較 → 鎖定、整理或換裝 → 看到角色能力立即變化 → 繼續觀察戰鬥與刷寶成果。

因此，戰利品、裝備比較與角色素質是主要資訊。桌機採左側戰鬥、右側管理，整理時戰鬥仍可見。管理區不是結束關卡後的結算頁；打開管理不能清除 G、重開關卡或隱式暫停。

新裝備要影響當前出戰角色的實際能力，而非僅更新選單數字。比較需使用正式公式；稀有度、戰力提升與流派適配是不同概念。新掉落不能搶走正在比較的選取物件，批次操作要辨識實際物品 ID。

轉蛋、升級、其他養成與系統仍需改版。它們在實作順序上較晚；最新「全版美術」要求已將角色／世界與各系統納入。不要沿用更早版本的暫緩敘述，把它們永久排除。

## 已定案的美術方向

保留 2D 美式粗硬街頭感：粗框、高對比平塗、粗重文字與短硬陰影。線條以圓角接筆、平順曲線呈現，收斂多餘尖刺、外凸角標、鋸齒爆框和大量斜切。這次是讓輪廓更順，同時保留已接受的份量與辨識度。

主操作與選取採淺藍，配合炭黑與冷白。稀有度、危險與增益維持各自語意，不能全部染成淺藍；數據背景保持乾淨，裝飾紋理放在邊緣。

淺藍方向、粗硬程度、左右布局由使用者確認；`#B9DFF6`、2～4px 線寬、圓角與約58／42布局比例是 v0.4 的設計落地值，可直接實作，並非使用者逐值指定。正式尺寸需依可讀性與既有程式整合。詳見 [ART-SPEC](../handoff/v0.4/ART-SPEC.md)。

## 全版範圍與原程式的事實

原碼為 JavaScript＋Canvas 2D，DOM 選單與 Canvas HUD 並存；Canvas 邏輯座標 800×450。已盤點 26 個面板節點（含空殼與舊入口）、5 職業、12 裝備部位、7 稀有度、9 寵物、5 神獸、10 場景主題、13 種敵方母型與 T 的 288 筆定義。

全版範圍包含 UI、提示／彈窗、圖示、玩家／外觀／轉職、敵人／夥伴、動作、HUD、危險預警、場景、掉落／傳送門、技能／命中特效、轉蛋、升級與其他事件動畫。47 列 [COVERAGE](../handoff/v0.4/COVERAGE.csv) 用於逐項記錄。26 個節點不等於 26 個獨立新功能；288 筆資料不等於 288 套獨立圖像。

原碼已有 `statsOf`、`cpWith`、`mkP/refreshP`，但換裝入口尚未統一連接在場能力刷新。`toMenu` 會清除 G；管理區生命週期需另行整合。`item.id`、背包滿／自動分解、Canvas 點擊座標、房主／訪客能力同步都是工程重點，詳見 [LIVE-GEAR](LIVE-GEAR.md)。

## 新實作端從哪裡開始

讀取 [START-HERE](../START-HERE.md) 與完整 [IMPLEMENTATION_PROMPT](../handoff/v0.4/IMPLEMENTATION_PROMPT.md)，先確認基準和資料映射，再按 M0～M5 推進：共用 UI／左右布局 → 即時裝備與掉落 → 全系統頁 → 全世界與特效 → 事件演出／完整驗收。

非升級換裝沿用現有機制保留 HP／MP 絕對值並限制到新上限，避免免費補滿、復活、清冷卻或怒氣。保持既有增益與攻擊快照取值時機，背包操作固定 ID；連線不能默默排除。這些是核心需求的工程落實規則，完整細節見 LIVE-GEAR 與 ACCEPTANCE。

每次完成一批，回報做了什麼、測了什麼、尚未完成什麼，更新 STATUS、COVERAGE 實作欄與必要 DECISIONS／ADR，提交至已配置且獲授權的 Git 遠端／分支。新聊天室有本文件及完整專案就能接手，不以重新取得聊天紀錄為前提。
