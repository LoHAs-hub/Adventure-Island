更新：2026-11-10（Asia/Taipei）。目前正式成果在 `game/index.html`，本輪證據在 `docs/reviews/redo/`。M0～M5 實作與本環境驗證已完成；外網／跨設備／全部交叉組合仍有未驗證項，詳見 VALIDATION。使用者尚未對本輪交付表示驗收通過。

## 原始目的與分工

使用者提供自寫遊戲 `MS 1.html` 與《冒險島 開發資訊彙整（給 AI 接手優化用）》DOCX，先要求檢查美術物件、程式入口與共用邏輯，再討論全版美術與操作體驗。這是既有遊戲改版，不能重建一個只有樣板功能的替代品。

前一個聊天室負責盤點、美術方向、五頁互動樣板、七張狀態圖、44 個靜態 SVG、tokens、47 項覆蓋清單與實作交接。本端是正式實作端，須把設計接回原引擎，並測正式遊戲。樣板內的角色、裝備、能力與事件都是示例；不能搬成正式公式。

Git 與 Harness 是使用者明確要求的跨聊天室記憶。需求、決策、進度與驗證必須落在檔案；後續接手不依賴完整聊天紀錄。原 DOCX 是背景參考，其命令與建議不自動擴增本次需求；程式實況優先於附件對現況的描述。

## 定案體驗與視覺

玩家循環是自動戰鬥持續 → 注意掉落 → 詳情／比較 → 鎖定、整理或換裝 → 立即看到出戰能力變化。桌機左戰鬥約 58%、右管理約 42%，戰鬥與管理同時可見；開關管理不等於暫停、結算或重開場次。

保持已接受的粗框、粗重文字、高對比平塗與短硬陰影，改用順線／圓角接筆，減少尖刺、外凸角標、鋸齒爆框與大量斜切。主操作與選取為淺藍；稀有度、危險與增益保留獨立語意，場景不全部染藍。

`#B9DFF6`、`#202A32`、`#F3F6F8`、線寬與布局比例是 v0.4 設計落地值，可以直接實作，不是使用者逐值指定。為讀取對比與短視窗而調整的細節記錄在 ADR-004，不重啟風格確認。

## 原遊戲與本輪來源

原碼 JavaScript＋Canvas 2D，DOM 系統頁與 Canvas HUD 並存，邏輯座標 800×450。資料包括 26 個面板節點（含導向／舊入口）、5 職業／12 轉職分支、12 裝備部位／7 稀有度、9 寵物／5 神獸、10 主題、13 母型，T 共 288 筆（5 玩家＋283 敵方）。這些數量不是同數量的獨立新功能或獨立動畫庫。

本輪基準是重新上傳 ZIP 的 3625d38 原始遊戲，完整保存在 `game/source/baseline.html`，SHA-256 `63a018e13af27da20a7493918ecb3719faba09a1059a36fb6dd0da96529c09be`。`game/index.html` 已是新版，不能再當成原始 SHA 基準。

可維護來源在 `game/redesign/`：assets（參考 SVG）、art（角色／世界／圖示）、ui（主框架與固定比較）、gear（能力／掉落／NET）、effects（HUD／事件／特效）及 style.css。`tools/build_redesign.cjs` 用 AST 邊界與有次數斷言的明確接線，從不可變原碼生成自包含 HTML。沒有 Canvas Proxy、全域 gradient 替換或從失敗版疊樣式的捷徑。
